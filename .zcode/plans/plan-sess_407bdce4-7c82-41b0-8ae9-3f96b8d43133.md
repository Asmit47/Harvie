# Harvie Architecture v2 (final) — Jev Gatekeeper + Learning + Dual-Lane Work/Chat + Proactive Loops

## Locked decisions
- **Jev** = TypeSafe AI System One model via `typesafe-sdk` (`TYPESAFE_API_KEY` provided by user; batched choice/score/noul questions, ~0.1s). Every Jev call has deterministic keyword fallback + `JEV_ENABLED` kill switch.
- **Supermemory stays the knowledge/memory layer** (Tier 3 unchanged) — no custom memory_entities/memory_edges/graph tables, no GET /memory/graph.
- **Jev selects which connected apps matter per task** — never query all seven suites blindly (turn-level tool subsetting AND heartbeat observation).
- **Dual-lane**: chat lane stays instant and conversational; delegated work runs as background tasks on separate threads; the user can chat ("what's the update on X?") while work is in flight.
- **Surfacing**: in-app feed + badge with action buttons; approvals are mechanical (pending_actions), not prompt-only.
- **Cadence**: 30-min heartbeat per user + morning briefing; learned preferences override.

## Target flow

```
/chat turn:  START → load_context (Jev gate: turn_kind, mode, relevant apps, context needs,
             model tier, learning gates, urgency) → generate_answer (subset tools, tiered model)
             ↔ tool_executor → persist → END → async post-turn worker (Jev-gated learning)

Work lane:   Jev turn_kind=work → task_runs row (queued) → instant "on it" reply in chat
             → background worker executes on its own thread id {user}:task:{task_id}
             → progress log, approval pauses, completion → feed item. Chat lane never blocked.
             Jev turn_kind=status_check → read task_runs → immediate progress answer.

Background (APScheduler in lifespan):
  heartbeat/user (30min): guards → Jev-selected sources → diff vs event_snapshots
    → Jev triage → internal loop auto-updates OR pending_action drafts → feed items
  briefing/user (daily, persona tz) → digest → feed item
```

## Phase 1 — Jev client + turn gate (speed + routing + app selection)

**New `harvie/core/jev.py`**
- Lazy `TypeSafeClient` singleton (mirror `_LazyLLM` pattern, `core/llm.py:68-105`); `jev_evaluate(state, questions)` with `JEV_TIMEOUT_SECONDS=2`; returns None on any failure → keyword fallback path.
- `gate_turn(...) -> JevTurnDecision` (Pydantic) — ONE batched call:
  - `turn_kind`: Choice(chat/work/status_check) — chat = answer now; work = delegate to background task (Phase 3); status_check = report task/loop progress
  - `mode`: Choice(research/status/action/answer/chat) — replaces keyword `detect_request_mode` (`context.py:13-23`)
  - **Relevant apps — one noul per suite**: gmail, calendar, docs, drive, tasks, slack, stripe, connected_apps, knowledge, open_loops, websearch ("is this app relevant to this user turn?"). Drives per-turn **tool subset binding** via new `tools_for_apps(decision)` in `harvie/tools/__init__.py` (39 tools → only the relevant slice; `ToolNode(ALL_TOOLS)` stays as executor safety net)
  - `checkup`: Noul — replaces `DAILY_CHECKUP_PHRASES` substring match (`load_context.py:35`)
  - `needs_knowledge`: Noul (skip Supermemory round trip; replaces regex `context.py:26-27`)
  - `needs_loops`: Choice(none/relevant/all); `needs_persona`: Noul (skip 3000-char block on light turns)
  - `model_tier`: Choice(quick/deep) — quick → Groq `openai/gpt-oss-20b` (new `_LazyLLM`, `GROQ_QUICK_LLM_MODEL`), deep → gpt-oss-120b; Gemini stays exception-fallback (delivers "Harvie picks per task")
  - `has_preference_signal`, `has_commitment`: Noul — gate post-turn learning
  - `urgency`: Score(0-3)
- `harvie/core/state.py` += `jev_decision: dict`. `load_context` calls gate first; `build_context(state, decision)` (None ⇒ today's behavior); `generate_answer` binds subset + tier model.
- Config: `TYPESAFE_API_KEY`, `JEV_MODEL="jev-latest"`, `JEV_ENABLED`, `JEV_TIMEOUT_SECONDS`, `GROQ_QUICK_LLM_MODEL` → `.env.example`, `render.yaml`, `requirements.txt` (+`typesafe-sdk`).

## Phase 2 — Learning v2 (off critical path; Supermemory untouched)

- **Remove inline big-model persona extraction from `/chat`** (`chat.py:402-405`). New `harvie/memory/learning_worker.py` daemon thread post-response, explicit `user_id`, dedup guard `agent_state["learning:{user}:{request_id}"]`. Runs only when Jev flags `has_preference_signal`/`has_commitment` (most turns: zero LLM cost).
- One structured-output call extracts: 11 persona fields (unchanged rules) + **arbitrary preferences** → `persona_profiles.profile.preferences` (JSONB, provenance-tracked — quiet hours, nudge taste, app priorities feed Jev state and heartbeat) + **commitments** → auto-create open loops (`source_type="conversation"`). Long-term knowledge keeps flowing to Supermemory via existing tools.

## Phase 3 — Dual-lane: background work tasks (chat stays free)

**New table `task_runs`** (id, user_id, title, objective, status[queued/running/waiting_approval/completed/failed], thread_id, progress JSONB (step log), result_summary, feed_item_id, request_id origin, created/updated_at) — idempotent DDL in `init_db`.

**New `harvie/tasks/runner.py`** — durable worker:
- Daemon worker loop (started in lifespan) polls `task_runs` WHERE status=queued `FOR UPDATE SKIP LOCKED` every 5s; small pool (2 concurrent tasks max); survives restarts (queue is Postgres-backed).
- Execution: invokes the existing compiled graph on its **own thread id** `{user_id}:task:{task_id}` with a work-mode system prompt (objective, allowed apps from Jev's gate, constraints). Does NOT take the per-user conversation advisory lock — chat never blocks. Writes progress steps; outbound/mutating steps create **pending_actions** and pause (status=waiting_approval); completion writes result_summary + feed item.
- Chat-side: `turn_kind=work` → insert task_runs row, reply instantly ("On it — I'll flag you when it's done") + task card data; `turn_kind=status_check` → read task_runs/progress, immediate answer (no heavy LLM).
- New `GET /tasks` + `GET /tasks/{id}` routes (feed panel and status answers use them). Optional `POST /tasks/{id}/cancel`.

## Phase 4 — Feed + pending actions (approvals are mechanical)

**Backend**
- Tables: `feed_items(id, user_id, kind[nudge/briefing/alert/update/task], title, body, priority, data JSONB, open_loop_id, task_id, pending_action_id, read_at, created_at)` and `pending_actions(id, user_id, kind, tool, arguments JSONB, status[pending/approved/rejected/expired], source[task/heartbeat], feed_item_id, decided_at, result JSONB)`.
- New `harvie/memory/feed.py` + `harvie/api/routes/feed.py`: `GET /feed` (+unread_count), `POST /feed/{id}/read`, `/read-all`; `GET /pending-actions`, `POST /pending-actions/{id}/approve|reject|edit`. Approve executes via the existing tool layer, enforcing the same allowlist + `{APP}_` prefix rails as `connected_apps/provider.py:43-52`.
- `attention_open_loops()` escalation writes feed items; task events (completed/waiting_approval) write feed items.

**Frontend**
- `lib/api.ts`: feed/pending-action/task clients + types; wire the dead `attention_items` field; sidebar unread badge (react-query 60s refetchInterval).
- `feed-panel.tsx` modeled on the landing's "Noticed" cards: inline Approve draft / Edit first / Flag it / Later buttons → pending-action endpoints; task progress shown for kind=task. Matches design.md glass spec.

## Phase 5 — Proactive loop runner

**New `harvie/loops/`**; APScheduler `BackgroundScheduler` in lifespan (also makes `cleanup_expired_sessions()` periodic). Config: `LOOP_ENABLED`, `LOOP_HEARTBEAT_MINUTES=30`, `LOOP_BRIEFING_HOUR=7`, per-user jitter.

**Heartbeat** per active user (persona row or session in 14d):
1. **Guard**: `pg_try_advisory_lock` (skip if chat/task in flight); respect preference quiet-hours/cadence/opt-outs.
2. **Observe — Jev-selected sources**: one batched Jev call picks which sources matter for this user now (from actually-connected apps + active tasks + preferences — e.g., gmail+calendar+stripe for an invoicing user, skip slack) instead of always hitting all 7 suites. Pulls via existing per-app providers.
3. **Diff** vs `event_snapshots` (add `user_id`, `source` cols, idempotent ALTER); mismatch checks on diffs only.
4. **Decide — Jev** ("No pings for the sake of pinging"): worth surfacing? action(ignore/nudge/update_loop/create_loop/draft_action)? priority?
5. **Act — split by blast radius**: internal (open loops: complete/snooze/create) auto-updates; anything outbound → pending_action draft + feed item, never auto-run.
6. **Remember**: fresh snapshots, `agent_state["loop:last_run:{user}"]`.

**Briefing** (`harvie/loops/briefing.py`): daily at `LOOP_BRIEFING_HOUR` in persona timezone — big-model digest over Jev-selected sources + loops + task statuses → feed item kind=briefing.

## Risks & guards
- Jev unavailable ⇒ keyword fallback everywhere; `JEV_ENABLED` kill switch.
- Work lane and heartbeat take no conversation lock; chat is never blocked (separate thread ids, SKIP LOCKED queue).
- Outbound actions mechanically gated behind pending_actions; connected-app rails enforced on approve-execute.
- Cost: Jev triage ~$0.0001/call; big model only on deep turns, gated learning, act-worthy diffs, briefing, and work tasks.
- All DDL idempotent; no migration framework.
- Deferred (landing promises, not tonight): BYO-provider settings UI, delegation plan-view UI, memory-graph visualization (Supermemory owns memory), local/self-hosted packaging.
- Claim consistency: landing "250+" vs README "580+" — recommend landing use the live directory count.
